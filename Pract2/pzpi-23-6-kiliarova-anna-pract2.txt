3 ОПИС ВИКОНАНОЇ РОБОТИ
     3.1 Вихідний програмний контекст
     У роботі використано власний програмний код з курсового проєкту «Interpol», реалізованого мовою C# у середовищі WinForms із використанням бази даних Microsoft Access (Interpol.accdb).
     Ключові форми проєкту:
- LoginForm — авторизація адміністратора;
- MainForm — пошук, фільтрація, сортування записів;
- Statistics — відображення статистичних звітів.
Під час аналізу були виявлені такі проблеми коду:
- дублювання логіки у сервісах авторизації;
- глибоко вкладені умовні конструкції у LoginForm;
- велика кількість switch-case із жорстким зв’язком між логікою побудови статистики та формою Statistics;
- слабка гнучкість коду при розширенні функціоналу.
3.2 Опис правил оформлення програмного коду
Під час рефакторингу застосовано такі підходи:
- дотримання C# Coding Conventions (Microsoft);
- правильний відступ (4 пробіли);
- зрозумілі та змістовні імена класів, методів та змінних;
- уникання зайвих вкладень;
- поділ відповідальності (SRP — Single Responsibility Principle);
- використання інтерфейсів для реалізації поліморфізму.
3.3 Програмні інструменти
Маємо такі програмні інструменти:
- Microsoft Visual Studio 2022 — середовище розробки;
- .NET Framework 4.7.2 — платформа виконання;
- WinForms — інструменти UI;
- Microsoft Access (ACCDB) — база даних;
- OleDbConnection — взаємодія з БД;
- GitHub — для зберігання програмного коду.
3.4 Застосування методу Collapse Hierarchy
     Проблема: у програмі існував базовий клас AuthService та підклас AdminAuthService, який повністю дублював логіку базового класу.
     Рішення: об’єднати класи – створити один повноцінний AuthService.
     3.5 Застосування Replace Nested Conditional with Guard Clauses
     Проблема: метод btnLogin_Click у LoginForm містив вкладені if, через що основний сценарій опинявся глибоко всередині.
     Рішення: використати Guard Clauses для ранніх виходів та спрощення логіки.
     Результат:
- прибрана вкладеність;
- покращена читабельність;
- легше додавати нові перевірки.
     3.6 Застосування Replace Conditional with Polymorphism
     Проблема: у конструкторі Statistics використовувався великий switch(num) із чотирма гілками для різних типів статистики.
     Рішення: створити інтерфейс IStatisticsReport та окремі класи для кожного виду статистики: CriminalStatisticsReport, CrimeStatisticsReport, WarrantStatisticsReport, CourtCaseStatisticsReport.
     Переваги:
- повне роз’єднання Statistics та логіки побудови звітів;
- легке додавання нового типу статистики;
- код став масштабованим і підтримуваним.

     В.1 Приклад коду до рефакторингу (Collapse Hierarchy)
     До застосування методу Collapse Hierarchy – зайва ієрархія класів AuthService / AdminAuthService:
 1  class AuthService
 2  {
 3      public virtual bool Authenticate(string login, string password)
 4      {
 5          // ...
 6      }
 7  }
 8
 9  class AdminAuthService : AuthService
10  {
11      // Фактично повторює базовий метод без змін
12      public override bool Authenticate(string login, string password)
13      {
14          return base.Authenticate(login, password);
15      }
16  }

     В.2 Код після рефакторингу (Collapse Hierarchy)
     Об'єднання логіки в єдиний AuthService:
  1  class AuthService
 2  {
 3      private readonly string _connectionString;
 4
 5      public AuthService(string connectionString)
 6      {
 7          _connectionString = connectionString;
 8      }
 9
10      public bool Authenticate(string login, string password)
11      {
12          const string query =
13              "SELECT COUNT(*) FROM admin WHERE login = @login AND password = @password";
14
15          using (var connection = new OleDbConnection(_connectionString))
16          {
17              connection.Open();
18
19              var command = new OleDbCommand(query, connection);
20              command.Parameters.AddWithValue("@login", login);
21              command.Parameters.AddWithValue("@password", password);
22
23              return Convert.ToInt32(command.ExecuteScalar()) > 0;
24          }
25      }
26  }

     В.6 Код після рефакторингу (Polymorphism)
     Інтерфейс та реалізація окремих звітів:

 1  public interface IStatisticsReport
 2  {
 3      string Title { get; }

 5  }
 6
 7  public class CriminalStatisticsReport : IStatisticsReport
 8  {
 9      public string Title => "Статистика про злочинців";

13  public class CrimeStatisticsReport : IStatisticsReport
