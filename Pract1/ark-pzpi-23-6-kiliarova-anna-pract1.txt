3 ОПИС ВИКОНАНОЇ РОБОТИ
     3.1 Вибір мови програмування
     Для виконання практичної роботи було обрано мову Python, оскільки вона широко використовується у веб-розробці (Django, Flask, FastAPI), має офіційний стандарт стилю PEP 8, а також добре підходить для демонстрації принципів чистого коду та рефакторингу.
     3.2 Основні рекомендації PEP 8 та їх пояснення
     3.2.1 Рекомендація 1. Використання осмислених імен змінних, функцій і класів
     Зрозумілі імена дозволяють швидко аналізувати логіку веб-застосунку. Некоректні назви ускладнюють підтримку API, моделей та бізнес-логіки.
1 # Поганий приклад
2 def f(u, p):
3     return u.c(p)
4
5 # Гарний приклад
6 def check_user_credentials(user, password):
7     return user.check(password)
     Конкретні назви знижують ризик помилок, полегшують роботу з великими веб-проєктами та покращують читабельність при командній розробці.
     3.2.2 Рекомендація 2. Використання відступів у 4 пробіли
     PEP 8 вимагає використовувати 4 пробіли, що забезпечує єдність стилю.
1 # Поганий приклад (змішані табуляції й пробіли)
2 if user.is_active:
3     do_something()
4         log()
5
6 # Гарний приклад
7 if user.is_active:
8     do_something()
9     log()
     Веб-фреймворки (Flask/Django) не терплять змішаних відступів і код стає передбачуваним для всіх учасників команди.
     3.2.3 Рекомендація 3. Максимальна довжина рядка – 79 символів
1 # Поганий приклад
2 result = service.process_user_request(request, database, cache, logger, permissions, config)
3
4 # Гарний приклад
5 result = service.process_user_request(
6    request, database, cache, logger, permissions, config
7 )
     Це полегшує читання коду у вузьких редакторах і значно покращує читабельність ревʼю.
     3.2.4 Рекомендація 4. Документування функцій за допомогою docstrings
1 # Гарний приклад
2 def login(username, password):
3     """
4     Перевіряє логін та пароль користувача.
5     Повертає True, якщо автентифікація успішна.
6     """
7     return authenticate(username, password)
     Docstring допомагає зрозуміти призначення API-ендпоінтів і сервісів без пошуку логіки в коді.
     3.2.5 Рекомендація 5. Коментарі мають пояснювати «чому», а не «що»
1 # Поганий приклад
2 x = x + 1  # додаємо 1
3
4 # Гарний приклад
5 # Компенсація зміщення години для часової зони користувача
6 user_time += timedelta(hours=1)
     Коментарі повинні пояснювати причину, а не очевидну дію. Допомагають майбутнім розробникам уникнути помилок.
     3.2.6 Рекомендація 6. Структура коду у веб-проєктах
1 # На прикладі Flask:
2 from app.services.auth import AuthService
3 from app.routes import user_routes
     Структура повинна включати:
- /routes/ – маршрути;
- /models/ – сутності даних;
- /services/ – бізнес-логіка;
- /utils/ – утилітарні функції.
     Це робить проєкт масштабованим та логічно зрозумілим.
     3.2.7 Рекомендація 7. Інструменти контролю стилю коду
     Основні:
- Flake8 – перевірка стилю;
- Black – автоформатування;
- Pylint – статичний аналіз;
- SonarQube – комплексна оцінка коду;
- Git Hooks – перевірки перед комітом.
     Ці інструменти гарантують дотримання PEP 8 автоматично.
3.2.8 Рекомендація 8. Приклади рефакторингу (до/після)
1 # До:
2 def get(u):
3     if u!=None:
4         return u.name
5     else:
6         return "none"
7
8 # Після:
9 def get_username(user):
10     if user is None:
11         return "none"
12     return user.name
Що покращено:
- іменування,
- логічна структура,
- читабельність,
- відповідність PEP 8.












ВИСНОВКИ
     У ході виконання практичного заняття було розглянуто основні правила оформлення коду Python згідно з PEP 8 та їх застосування у веб-програмуванні. Отримано практичні навички правильного форматування, іменування, структурування та документування коду.
     Було проаналізовано приклади некоректного оформлення коду та виконано їх рефакторинг. Освоєно використання інструментів автоматичної перевірки стилю, що допомагають підтримувати якість та читабельність веб-застосунків.
     У результаті сформовано розуміння важливості дотримання стилістичних рекомендацій для створення надійного, підтримуваного та ефективного програмного забезпечення.
