1 ЗАВДАННЯ
        Метою лабораторної роботи є набуття практичних навичок розгортання програмної системи, налаштування її серверних та клієнтських компонентів, а також демонстрації роботи реалізованого функціоналу відповідно до вимог документа Vision & Scope.
У межах роботи виконується розгортання backend-частини системи, перевірка роботи IoT-клієнта та демонстрація взаємодії між компонентами системи через REST API.








































2 ОПИС ВИКОНАНОЇ РОБОТИ
Серверна частина програмної системи FreshFridge реалізована на платформі Node.js з використанням фреймворку Express.
Для розробки та тестування застосунку було використано локальне середовище виконання з доступом до API через Swagger UI.
Репозиторій проєкту (див. рис. 2.1) містить реалізацію основних модулів системи, зокрема:
* модуль автентифікації та авторизації користувачів;
* модуль управління холодильниками;
* модуль прийому та збереження IoT-телеметрії;
* модуль сповіщень та аналітики.
  

Рисунок 2.1 – Репозиторій та серверна частина програмної системи FreshFridge
Для документування та тестування REST API було використано Swagger UI, який надає можливість перегляду доступних endpoint-ів та виконання запитів безпосередньо з браузера (див. рис. 2.2).
  

Рисунок 2.2 – Swagger-документація серверної частини FreshFridge
        Для реалізації та тестування IoT-клієнта було використано онлайн-емулятор Wokwi, який дозволяє моделювати роботу мікроконтролера ESP32 та підключених до нього датчиків (див. рис. 2.3).
* IoT-клієнт включає:
* мікроконтролер ESP32;
* датчик температури та вологості DHT22;
* перемикач, що імітує стан дверцят холодильника.
IoT-клієнт періодично зчитує дані з датчиків та формує JSON-повідомлення, яке надсилається на сервер за допомогою HTTP POST-запиту на endpoint /api/iot/telemetry.
  

Рисунок 2.3 – IoT-клієнт системи FreshFridge у середовищі Wokwi
        Для забезпечення взаємодії між IoT-клієнтом та локально розгорнутим сервером було використано Cloudflare Tunnel, який надає публічний HTTPS-доступ до локального сервера.
У програмному коді IoT-клієнта налаштовано:
* адресу сервера через Cloudflare Tunnel;
* передачу JWT-токена у заголовку Authorization;
* передачу ідентифікатора холодильника fridge_id.
Після надсилання телеметрії з IoT-клієнта було виконано GET-запити через Swagger для отримання:
* історії телеметричних даних холодильника;
* останнього збереженого знімку телеметрії.
Отримані дані повністю відповідають показникам, що надсилаються IoT-клієнтом, що підтверджує коректну роботу серверної частини та бази даних (див. рис. 2.4).

ВИСНОВКИ
У ході виконання лабораторної роботи №5 було набуто практичні навички розгортання програмної системи та налаштування її компонентів.
Було розгорнуто та протестовано серверну частину системи FreshFridge, перевірено роботу REST API за допомогою Swagger, а також реалізовано та протестовано IoT-клієнт у середовищі Wokwi.
Забезпечено повний цикл обміну даними між IoT-пристроєм та сервером, включаючи автентифікацію, передачу телеметрії та її подальше отримання. Отримані результати підтверджують коректну інтеграцію всіх компонентів програмної системи та готовність проєкту до подальшого розвитку.
